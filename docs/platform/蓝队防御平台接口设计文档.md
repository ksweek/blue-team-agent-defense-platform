# 蓝队防御平台接口设计文档

本文档描述当前代码中已经落地、可以直接联调的后端接口，而不是远期设想。

截至 `2026-06-20`，后端基于 `FastAPI + SQLAlchemy + JWT + 嵌入式/外置 Worker + 多 Provider 配置 + Gateway + Runtime Bridge + MCP Ticket`，已经覆盖认证、策略、防御配置、AI 目标、Runtime 接入、统一代理、资产、技能、样本、任务、事件、报告和系统设置等主链路。

## 1. 基本约定

### Base URL

- 本地后端：`http://127.0.0.1:8000`
- 业务接口前缀：`/api`

### 认证方式

除登录接口外，其余接口默认使用：

```http
Authorization: Bearer <access_token>
```

### 统一响应结构

成功：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

失败：

```json
{
  "code": 4003,
  "message": "resource not found",
  "data": null
}
```

### 常见错误码

| 错误码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `4002` | 参数错误 |
| `4003` | 资源不存在 |
| `5001` | 服务内部错误 |

### 请求追踪

后端会回传 `X-Request-ID`，并在命令行日志中带上同一个请求标识，便于排查请求链路。

## 3.1 入口安全、限流与缓存约定

- `/api` 业务接口默认使用平台 JWT；登录接口、`/api/runtime-registry/activate` 和 `/api/runtime-registry/client-activate` 除外。
- `/gateway/v1` 统一代理接口支持平台 JWT、内部服务令牌和 Runtime 长期凭据，最终是否放行仍取决于目标策略、预检规则、AI 审查和输出脱敏结果。
- 登录、公开 Runtime 注册/激活、请求体大小、WebSocket 消息大小、Host 白名单、响应安全头和验证错误脱敏都已经在中间件层落地。
- 敏感查询参数、验证错误详情和安全报告展示字段会做脱敏处理，避免 token、secret、password 等字段直接出现在响应或日志中。
- 缓存服务优先使用 Redis；当未配置 Redis 或连接失败时，会回退到进程内缓存，适合本地开发但不适合作为多实例生产缓存。

## 4. 认证接口

### `POST /api/auth/login`

说明：

- 校验数据库中的账号和密码
- 返回 JWT、过期时间和当前用户信息

请求示例：

```json
{
  "username": "admin",
  "password": "admin_123"
}
```

返回重点字段：

- `access_token`
- `token_type`
- `expires_at`
- `user.id`
- `user.username`
- `user.roles`
- `user.pages`

### `GET /api/auth/me`

说明：

- 读取当前登录用户
- 返回角色和可访问页面列表

## 7.1 AI 目标与 MCP 策略接口

### `GET /api/ai-endpoints`

支持参数：

- `page`
- `page_size`
- `status`
- `provider`
- `keyword`

说明：

- 返回平台托管的 AI 目标、Provider 配置、模型名、连接状态和字段元数据。
- 列表结果会经过缓存服务；多实例部署建议启用 Redis。

### `POST /api/ai-endpoints`
### `PUT /api/ai-endpoints/{endpoint_id}`
### `DELETE /api/ai-endpoints/{endpoint_id}`

作用：

- 新增、更新或删除托管 AI 目标。
- 删除目标时会同步清理关联 MCP 策略行。

### `POST /api/ai-endpoints/batch-update`

作用：

- 批量启用、禁用或修改 AI 目标状态。

### `POST /api/ai-endpoints/{endpoint_id}/test`

作用：

- 对指定 AI 目标发起连通性测试。
- 测试结果会回写目标的健康状态和最近错误摘要。

### `GET /api/ai-endpoints/{endpoint_id}/mcp-policy`
### `PUT /api/ai-endpoints/{endpoint_id}/mcp-policy`
### `POST /api/ai-endpoints/{endpoint_id}/mcp-policy/apply-template`

作用：

- 读取、更新或按模板应用目标级 MCP server / capability 策略。
- Gateway 与 Runtime 回调会基于该策略决定是否签发或校验一次性 MCP 执行票据。

## 12. Runtime、Gateway 与 OpenAI-compatible 入口

- 授权阶段会执行策略判断，必要时签发 MCP 一次性执行票据。
- 完成阶段会校验 MCP 票据、写入事件、生成报告并更新任务状态。

### `GET /api/runtime-registry`
### `POST /api/runtime-registry/activation-requests`

### `POST /gateway/v1/chat/completions`

### `POST /gateway/v1/runtime/register`
### `POST /gateway/v1/runtime/register/status`

## 13. 当前接口边界

- 报告导出与系统动作工件都已支持真实文件下载；执行动作接口本身仍返回结果结构，文件需要走对应下载接口获取。
- Provider 层以 OpenAI-compatible Chat Completions 为核心；Gateway 已提供 Responses / Agent Run 兼容入口，但复杂 Provider 差异归一化仍需要继续补齐。
- Worker 支持嵌入式线程和独立进程部署；本地 SQLite 在高并发写入时仍可能出现 `database is locked`，生产环境应使用 PostgreSQL + Redis。
- 报告模板已支持 JSON / HTML / DOCX，但还没有 PDF、正式签章流转和对象存储归档形态。
- Gateway、Runtime、MCP Ticket 已形成最小闭环；生产级 HA、跨实例任务抢占、死信队列和多租户隔离仍是后续工程重点。

## 14. 最值得继续补的接口

1. PDF / 正式版报告渲染、签章流转与对象存储下载接口。
2. 任务超时回收、死信转移、跨实例抢占与多 Worker 调度接口。
3. 多 Provider 响应协议统一、错误码归一和更细粒度成本统计接口。
4. Runtime 命令队列的批量拉取、租户隔离和审计追踪接口。
5. Gateway WebSocket 的长连接观测、限速和熔断管理接口。
